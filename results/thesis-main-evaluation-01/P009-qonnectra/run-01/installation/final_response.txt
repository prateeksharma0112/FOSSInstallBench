## What was done
The guide's primary Quick Start (`docker compose up -d --build`) uses the production compose file, which cannot start in this environment because every service sets `deploy.resources.limits.memory`, and the host cgroup is in **cgroup v2 "threaded" mode** (`domain threaded`), so runc fails with `cannot enter cgroupv2 "/sys/fs/cgroup/docker" with domain controllers`. I therefore used the guide's **Documented Method 2** (`docker-compose.dev.yml`, "Docker Compose Development with Local HTTPS"), which has no `deploy` limits.

Three genuine repository defects blocked that method and were fixed:
1. `deployment/postgres/Dockerfile` used `postgis/postgis:17-3.5` (Debian bullseye), whose upstream PGDG apt repo `bullseye-pgdg` has been **removed** (404) — `apt-get install postgresql-17-pgrouting` failed (exit 100). Also, the pool `.deb` requires `libstdc++6 >= 13.1` while bullseye ships 10.2.1 (`GLIBCXX_3.4.32 not found`). Fixed by switching the base to `postgres:17-bookworm` and installing `postgresql-17-postgis-3` + `postgresql-17-pgrouting` from the live `bookworm-pgdg` repo.
2. `deployment/postgres/init.sh` unconditionally ran `REVOKE ALL ON model_permission/route_permission` before Django migrations create those tables; with `set -e` + `ON_ERROR_STOP=1` the first-time DB init aborted and the `db` container exited(3). Fixed with `to_regclass(...)` guards.
3. `deployment/docker-compose.dev.yml` had three blocking bugs: (a) nginx mounted `nginx.conf` into `/etc/nginx/conf.d/default.conf` (`worker_processes` not allowed there → restart loop); (b) the `qgis-server` heredoc terminator `EOF` was indented so the heredoc never closed; (c) the shared `nginx/default.conf` references a `backend-wms` upstream that the dev compose did not define. Fixed by mounting both nginx files correctly, replacing the heredoc with `printf`, and adding the missing `backend-wms` service.

Additional environment handling: created `deployment/.env`; set `API_URL=http://backend:8000/api/v1/` (the container-internal address the production template documents) and rebuilt the frontend, because the server-side URL `https://api.localhost` is unresolvable inside the frontend container (ENOTFOUND). Installed OpenJDK 21 and generated base map tiles with Planetiler to satisfy the documented TileServer-GL prerequisite (the repo ships no `*.mbtiles`), then placed them as `germany.mbtiles` as referenced by `tiles/config.json`/styles.
