## Validation Report: Harbor v2.15.0 local deployment

**assessed_outcome: success**

The Harbor installation is complete and fully operational according to the supplied guide.

### Evidence obtained

**Containers (all 9 healthy):** `docker ps` and `docker compose ... ps` show the `harbor-local` compose project running all expected services as healthy: core, portal, jobservice, registry, registryctl, trivy-adapter, exporter, postgresql, redis. Portal publishes 80->8080 and 443->8443.

**API health:** `curl http://localhost/api/v2.0/ping` → `Pong` (HTTP 200). `curl http://localhost/api/v2.0/health` → HTTP 200 with every component (`core`, `database`, `jobservice`, `portal`, `redis`, `registry`, `registryctl`, `trivy`) reporting `"status":"healthy"`.

**Web UI:** `curl http://localhost/` → HTTP 200 with `<title>Harbor</title>`.

**Authentication:** `curl -u admin:Harbor12345 http://localhost/api/v2.0/projects` → HTTP 200 with the `library` project and `repo_count:1`. Docker `echo 'Harbor12345' | docker login localhost:80 -u admin --password-stdin` → `Login Succeeded`.

**Push/Pull workflow (guide section):** Tagged `alpine` as `localhost:80/library/alpine:val<ts>`, pushed (exit 0, registry digest returned), removed the local image, then pulled it back successfully (`Status: Downloaded newer image`). `docker rmi`/`docker pull` both exit 0. This confirms the registry is genuinely storing and serving OCI artifacts, not just accepting connections.

**Config artifacts:** `.env` created from `.env.example` with `IMAGE_REPO=8gears.container-registry.com/8gcr/`, `HARBOR_TAG=v2.15.0`, TLS disabled via `/dev/null` mounts, matching the guide. `deploy/compose/config/token_service_key.pem` exists as a valid traditional RSA key (mode 644) as required.

**Logs:** Scanned core/jobservice/registry/portal logs for error/fatal/panic — no error entries found.

### Assessment rationale
The final method used was the guide's Manual Start (Docker Compose) path with the documented remote image repo, which is an explicitly supported variant. Every component the guide requires is present, considered healthy by Harbor's own health endpoint, and the documented push/pull behavior was reproduced end-to-end with a fresh artifact. No incomplete or repair-requiring state was observed. The only deviation noted (task CLI not installed, manual equivalent commands used) is allowed and does not affect the result.

### Limitations
- The `.env`/`.env.example` inspection excluded lines containing "password" only for display brevity; login credentials printed in the guide (admin/Harbor12345) were confirmed working.
- Optional HTTPS/mkcert configuration was not applied, but the guide marks it as optional; TLS-disabled mode is the guide's default and is fully functional.
- The 401 on `/v2/_catalog` is expected (auth required) and not a defect; authenticated API and Docker flows succeeded.
