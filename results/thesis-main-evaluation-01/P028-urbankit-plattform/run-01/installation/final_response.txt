UrbanKIT Plattform was installed via the documented Docker Compose method and verified running.

What I did:
- Copied `.env.example` → `/workspace/.env` and set the required secrets (`PAYLOAD_SECRET`, `HOCUSPOCUS_SECRET`). `NEXT_PUBLIC_SERVER_URL` and `NEXT_PUBLIC_HOCUSPOCUS_URL` already had valid development defaults.
- Ran `docker compose up -d --build` (base compose file). All four images built successfully: `workspace-web` (multi-stage Next.js 15 + Payload build), `workspace-hocuspocus`, plus pulled `mongo:7` and `axllent/mailpit`.
- The first start attempt failed with a sandbox-specific error: `unable to apply cgroup configuration: cannot enter cgroupv2 "/sys/fs/cgroup/docker" with domain controllers -- it is in threaded mode`. This is caused by the `deploy.resources.limits` blocks in `docker-compose.yml` combined with this environment's cgroup v2 being mounted in threaded mode. I added a local, non-upstream `docker-compose.override.yml` that resets those `deploy.resources.limits` blocks (using `!reset {}`) and re-ran `docker compose up -d`, which succeeded.

Verification (all objective, exit-code based):
- `docker compose ps` → web (healthy, 127.0.0.1:3020), mongo (healthy, 127.0.0.1:27019), hocuspocus (up, 127.0.0.1:1234), mailpit (healthy).
- `curl http://localhost:3020/api/health` → HTTP 200 `{"ok":true}`.
- `Host: urbankit.de` → 307 to `/de`, then HTTP 200 portal HTML (`<title>UrbanKIT – Stadtbeteiligung für Detmold</title>`), confirming domain routing works.
- `Host: app.urbankit.de` → 307 to `/dashboard`, then HTTP 200.
- `/admin` → HTTP 200; `/api/users` → HTTP 403 (Payload connected to Mongo, auth enforced).
- Hocuspocus WebSocket sidecar logs "Hocuspocus v2.15.3 running ... Ready" and responds HTTP 200 on port 1234.

Note: the stack runs; the only deviation from the guide is the added override file removing memory limits, which is required for containers to start in this sandbox.
