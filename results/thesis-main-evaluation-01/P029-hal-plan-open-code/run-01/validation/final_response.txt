- `SESSION_KEY` and `CRYPTO_SECRET` are real 32-byte hex values, not the `.env.defaults` placeholders (confirmed via diff).

**Generated artifacts**
- Prisma client present (`node_modules/.prisma/client/*`); `shared/graphql/types.ts`, `api/lib/graphql/schema.graphql`, `web/lib/graphql/gql.ts` generated (committed files); `web/public/web-ifc/*.wasm` present and served.

**Runtime behavior (primary evidence)**
- Dev server (`pnpm dev` / tsx api server) process alive ~2m40s; log shows "Server listening at http://127.0.0.1:3000", plugins/routes/audit-triggers/jobs managers loaded with no errors.
- `GET /`, `/map`, `/login` → HTTP 200; HTML is the real app shell (Buildplace meta, `/src/main.tsx`), and `/src/main.tsx` is served transformed by Vite (deps optimized).
- GraphQL at `/api/graphql`: `{ __typename }` → `{"data":{"__typename":"Query"}}` (introspection disabled by design).
- **Authentication works end-to-end**: `POST /api/auth/login` with seeded `tenantAdmin@buildplace.io` / `somepassword` → `{"success":true}` + session cookie; with cookie, `GET /api/auth/current-user` → correct user+tenant+role; authenticated GraphQL `user(id:…)` returned the correct record. Wrong password → `Unauthorized`; unauthenticated `user` query → "Not authorized". This matches the guide's "Working authentication (login with your configured dev user)".

- Production build (`pnpm build`/`pnpm start`) was not exercised — the documented dev path was used.
