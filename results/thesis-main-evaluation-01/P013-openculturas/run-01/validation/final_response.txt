## OpenCulturas Installation Validation Report

**Assessed outcome: success**

The OpenCulturas Drupal distribution is installed, complete, and operational in the container. The validation used the DDEV development method (`ddev composer install` + profile install), which is a documented path (README line 189, CLAUDE.md "ddev composer run si").

### What was inspected
- DDEV project/containers, Drupal bootstrap, database, modules, themes, config
- HTTP behavior of all advertised features (events, calendar, magazine, profiles, community, locations/maps, search, multilingual)
- Authenticated (admin) UI access via `drush uli`
- Content, assets, libraries, platform requirements, and error logs

### Key evidence
- **Runtime:** `docker ps` — `ddev-openculturas-web` (drupal11, PHP 8.4, nginx-fpm), `ddev-openculturas-db` (mysql 8.0) both healthy. `ddev drush core:status`: Drupal **11.3.17**, Database **Connected**, bootstrap **Successful**, profile **openculturas**, theme **opcult**, admin theme **gin**.
- **Modules/content:** 175 modules enabled; all **165** modules declared in the profile's `install` list are enabled (verified via `drush php:script`). 17 nodes, 68 terms, 2 media, 2 users.
- **HTTP (200 OK):** `/en` → `<title>Welcome | OpenCulturas</title>`; `/de` → `Willkommen`; `/user/login`; `/en/events`, `/en/calendar`, `/en/locations`, `/en/magazine`, `/en/magazine/hello-world`, `/en/community`, `/en/categories`, `/en/search`. Pages render themed markup with no fatal errors/PHP exceptions.
- **Auth:** `ddev drush uli` produced a valid login URL; authenticated requests to `/en/admin/content`, `/en/node/add/event`, `/en/admin/people`, and map settings page returned 200.
- **Search:** index initially 0/32; after a normal `drush cron` it reached 100% (32/32) and the search view returns results.
- **Maps feature:** `leaflet` + `leaflet_views` enabled, map view modes/config present; map REST export `rest/oc_map_locations` returns HTTP 200 `[]` (valid, empty because no location nodes exist).
- **Health:** `drush updatedb` → "No pending updates"; `cache:rebuild` → success; `ddev composer check-platform-reqs` → all requirements success on PHP 8.4.24. `watchdog` shows no application errors (the only severity-3 entry is from my own malformed `php:eval` probe).

### Limitations / unresolved uncertainty
- **Config drift:** 193 items only-in-sync, 49 only-in-db, 96 differing (ignoring uuid/_core). This is a known consequence of the profile-install path versus the committed full config export (mostly optional-module config and theme-prefix differences); it does not impair operation.
- The guide's alternate command `ddev drush site:install --yes --existing-config` is reported broken (geocoder service ordering); I did **not** reproduce it because running it would destroy the working site, which the validation boundaries forbid. The alternate documented method succeeded.
- Optional/experimental feature modules `openculturas_openstreetmap` (lifecycle: experimental), `openculturas_faq`, `openculturas_discussions`, `openculturas_section` are disabled — but they are not in the profile's default install list (its install hook only installs `openculturas_map`, which is enabled), so the installed state matches canonical profile-install behavior.

### Reasoning
Objective evidence demonstrates the software is installed completely and operates: it bootstraps, serves all headline feature pages over HTTP, accepts authentication, exposes an admin UI, has a built search index, and shows no runtime errors. The single documented-but-broken install variant is an upstream ordering bug for this commit, not a defect in the delivered installation, and a documented alternative path was used successfully. Residual config drift and disabled optional modules are consistent with the chosen canonical install method rather than indicating an incomplete installation.
