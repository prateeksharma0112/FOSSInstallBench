### Reported failing specs and root cause (not an install defect)

Specs `030-fachplanung_erstellen` (1/3), `031` (0/6), `032` (0/2), `033` (0/1) fail. I traced the cause:
- Container clock is **2026** (`Tools::getCurrentYear()` → 2026), so the only permitted new plan year is 2027.
- The docs helper `scripts/setup_docu_data.php` inserts a 2026 plan *directly via SQL* (`INSERT INTO gesamtplan …`), bypassing `GesamtPlan::createGesamtplan`, so it has **zero `dynform_field` rows**. The test hardcodes 2027.
- Consequence: `FachPlanung::copyMassnahmen` builds `INSERT INTO massnahme (…,full_text,) SELECT …` — with an empty dynamic-field list this leaves a **trailing comma → DB error 1064**, surfaced as "Datenbank-Fehler (2)". Downstream specs then fail because no Fachplanung/measure exists.
- I proved this is data/clock-dependent, not an app defect: with a predecessor plan that has field definitions, `addFachPlanung('9901', 2024)` returns **OK** and copies rows. Following the guide's dump state (2023/2024, which do have 33+50 field rows), the create-plan→create-Fachplanung workflow inherits fields correctly.
