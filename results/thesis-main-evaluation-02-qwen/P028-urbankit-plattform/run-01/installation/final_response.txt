Installation of UrbanKIT Plattform completed successfully via the documented Docker Compose setup, with one local workaround required for the sandbox's cgroup-v2 threaded-mode limitation.

**What was done** (working directory /workspace, Ubuntu 22.04 sandbox, Docker 29.7.2 + Compose v5.5.0):
1. `cp .env.example .env`; set required vars — random 64-hex `PAYLOAD_SECRET` and `HOCUSPOCUS_SECRET`, `NEXT_PUBLIC_HOCUSPOCUS_URL=ws://localhost:1234` (default), `NEXT_PUBLIC_SERVER_URL=http://localhost:3020` (mapped host port).
2. `docker compose up -d --build` — all images built successfully (web Next.js 15.4.11 multi-stage image, hocuspocus sidecar image; mongo:7 and axllent/mailpit pulled).
3. **Obstacle:** every container creation failed with `runc create failed: unable to apply cgroup configuration: cannot enter cgroupv2 "/sys/fs/cgroup/docker" with domain controllers -- it is in threaded mode`. Bisected with minimal runs: `docker run --rm busybox true` works, `docker run --rm --memory 1g busybox true` fails identically — the sandbox's cgroup-namespace root cgroup is in v2 "threaded" mode, and runc cannot write cgroup limits (the compose files' `deploy.resources.limits.memory`) in that state. The threaded state could not be cleared from inside the namespace (writes to `cgroup.threads` are no-ops).
4. **Workaround:** created `/workspace/docker-compose.noresources.yml` (local-only, follows the guide's own multi-file `-f` pattern) with `deploy: !reset null` for web/hocuspocus/mongo/mailpit, then `docker compose -f docker-compose.yml -f docker-compose.noresources.yml up -d`.

**Verification results:**
- `docker compose ps`: web `Up (healthy)`, hocuspocus `Up`, mongo `Up (healthy)`, mailpit `Up (healthy)`
- `curl http://localhost:3020/api/health` → HTTP 200 `{"ok":true}`
- Domain routing: `Host: urbankit.de` → 307 → `/de` 200 ("UrbanKIT – Stadtbeteiligung für Dettold" portal); `Host: app.urbankit.de` → 307 → `/de/login` 200
- Hocuspocus: HTTP 200 on 127.0.0.1:1234, logs show "Hocuspocus v2.15.3 running … Ready."

Services run under loopback ports 127.0.0.1:3020 (web), 1234 (board WS), 27019 (mongo), 1025/8025 (mailpit). The production override (docker-compose.prod.yml) was not used — it is the documented VPS-only variant (Mongo root auth, no host Mongo port); the primary documented setup method was followed.
