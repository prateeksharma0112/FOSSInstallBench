Qonnectra installed successfully via Docker Compose (development stack with local HTTPS) in /workspace/deployment. All 9 services are up and verified: db (healthy), backend, backend-wms, frontend, nginx, qgis-server (healthy), tileserver (healthy), caddy, pg-error-parser. Verified end-to-end: frontend login page renders (app.localhost), DRF API returns 200 with JWT login working (api.localhost), Django admin redirects to login (admin.localhost), QGIS WMS responds correctly, tileserver serves tilejson, WebDAV returns 401 unauth / 207 PROPFIND auth (files.localhost), and an authenticated API call returned real project data from the migrated PostGIS database.

Several repository defects had to be fixed to complete the documented installation:
1. deployment/postgres/Dockerfile: base image postgis/postgis:17-3.5 (Debian bullseye, EOL) references the bullseye-pgdg apt repo, which apt.postgresql.org has removed (404). Pointed the source to the official PGDG archive (apt-archive.postgresql.org) which still serves the signed bullseye suite; pgrouting 3.8.0 installs and CREATE EXTENSION pgrouting works.
2. deployment/postgres/init.sh: REVOKE ALL ON model_permission/route_permission fails on fresh install (tables created later by Django migration 0057), aborting DB init (exit 3). Made the REVOKEs conditional on table existence.
3. deployment/docker-compose.dev.yml: (a) nginx service mounted the full main nginx.conf as a site conf → "worker_processes not allowed here"; now mounts nginx.conf as main config plus default.conf; (b) qgis-server command used a folded scalar that broke its <<EOF heredoc (EOF terminator merged into content line, rest of command swallowed); rewritten as explicit list with printf; (c) backend-wms service was missing although nginx/default.conf defines upstream backend_wms; added it mirroring the production compose.
4. tiles/germany.mbtiles is user-generated (Planetiler, per deployment/README.md, not in repo); created a minimal valid empty MBTiles placeholder so tileserver starts (real basemap data still requires Planetiler).
Also extended DJANGO_ALLOWED_HOSTS in deployment/.env with app.localhost, files.localhost, qgis.localhost, tiles.localhost (required by the dev Caddyfile's forward_auth subrequests; the documented .env example omits them), and applied the intended one-off REVOKE on the permission tables for qgis_user.
