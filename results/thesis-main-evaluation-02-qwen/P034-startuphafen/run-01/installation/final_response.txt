Startuphafen is installed and running end-to-end in a dev environment reproducing the documented devcontainer architecture.

What was done:
1. Installed Node.js 20 (NodeSource) on the host (repo has no node preinstalled); `npm install` completed (~1400 packages).
2. Built the backend (`npx nx run startuphafen-backend:build:development`).
3. Created a working compose file `.devcontainer/dev-fixed.yml` mirroring the documented devcontainer (dev-compose.yml + backend assets/docker-compose.yml): caddy, database (pgvector/pgvector:pg15), keycloak-database (postgres 15.5), keycloak (quay.io/keycloak/keycloak:26.1.2), maildev, pgadmin, plus a `devcontainer` service (same base image, mcr.microsoft.com/devcontainers/typescript-node:20-bookworm) where the apps run so `database`/`keycloak`/`maildev` hostnames resolve and caddy proxies to `devcontainer:5000/4201`.
4. Created the repo-referenced-but-missing `.devcontainer/keycloak/entrypoint.sh` (start-dev --import-realm, port 8180, theme cache disabled) and copied the keycloak theme into `.devcontainer/keycloak/themes`.
5. Fixed the Keycloak dev-realm import failure (`ModelException: invalidPasswordMinSpecialCharsMessage`): KC 26 validates imported user credentials against the realm password policy, and the documented dev passwords (admin/alice/marie) violate it. Relaxed the dev realm `passwordPolicy` to `length(5)` in `.devcontainer/keycloak/imports/startuphafen.json`; import then succeeded.
6. Created `.localConfigs.json` per the guide, adjusted to the current zod schema (template is stale: `bufaNr` must be a number and `jurisdiction` an array → used `finanzaemter: []`; the `mistral` block with empty `apiKey` crashes startup, so it was omitted — the app degrades gracefully with "chat/hwk-ai will not work" warnings).
7. Started the apps inside the devcontainer with the documented scripts `npm run back` and `npm run front`.

Verified: caddy :4000 serves the Angular frontend (200, title "Startuphafen"), proxies tRPC (FeatureFlags.getFeatureFlags 200 with real DB data, 6 flags), and /kc-admin (302). Keycloak :28080 serves JWKS (200), accepts password-grant logins as alice and admin (200), login page uses the startuphafen theme. Postgres has 57 migrations applied, 13 tables (FeatureFlag, Project, ShUser, VectorEmbedding, …). Backend log: `[ ready ] http://0.0.0.0:5000`; pgvector extension enabled. pgadmin on :3838, maildev on :1080 up (its healthcheck fails only because the v3 image dropped the `healthz` route the compose references).

Access points: caddy proxy http://localhost:4000 (development), keycloak direct :28080, keycloak admin http://localhost:4000/kc-admin (admin/admin), pgadmin :3838 (pgadmin@example.com/secret), maildev :1080. Dev logins per README: admin/admin, alice/alice (activated), marie/marie (not activated).

Known limitations (by design of the open-source release): no strapi/ERiC/OZG/Mistral credentials configured (placeholder/dev mode), chatbot & HWK pre-check degraded without a Mistral key, ERiC gateway and ELSTER certificate out of scope.
