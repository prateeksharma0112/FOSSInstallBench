## Method
Followed the Installation.md flow (Ubuntu path): copy archive to a dedicated instance directory, run `install.sh` as root, complete the web installer.

## Environment
- Ubuntu 22.04.5 LTS container, PID 1 = `tini`, **no running systemd** (`systemctl` absent, no `/run/systemd/system`). Root user. Qisutu source (v2.0.2, SHA 9df2635) pre-checked-out at `/workspace`.
- To run the systemd-dependent installer in this environment, a minimal, logging `systemctl` shim was created at `/usr/local/bin/systemctl` (maps `apache2`/`mariadb` to direct process management via `apachectl`/`mariadbd`, daemon services to `runuser`+pidfile under `/run/qisutu/`, records every call in `/var/log/qisutu-systemctl-shim.log`).

## Actions
1. `cp -a /workspace /opt/qisutu` (guide's recommended production path → instance id `qisutu`, web path `/qisutu`, DB `qisutu`).
2. `chmod +x /opt/qisutu/install.sh /opt/qisutu/update.sh` (checkout lacked exec bits; script itself also chmods after start).
3. `cd /opt/qisutu && QISUTU_INSTALL_LANGUAGE=de ./install.sh` → exit 0 ("Die Systemvorbereitung für die Instanz 'qisutu' wurde erfolgreich abgeschlossen"). Installed apache2, mariadb-server/client, Perl + `Authen::SASL`/`Net::LDAP`/DBI modules; created system user `qisutu` (in `www-data`); enabled Apache site `qisutu.conf` (ScriptAlias `/qisutu` → `/opt/qisutu/bin/cgi-bin/`); created `/etc/systemd/system/qisutu-daemon.service` + temporary `qisutu-install-complete.path/.service`; generated `var/secure/security.key`; created temporary bootstrap DB user (`var/install/database-bootstrap.conf`).
4. Drove the 6-step web installer non-interactively with `curl` (session cookie + CSRF token): 1) `Action=Begin` (system checks), 2) `AcceptLicense`, 3) `InstallDatabase` with `UseBootstrap=1` (DB `qisutu`, user `qisutu`, random passwords; schema.sql + insert.sql imported; bootstrap user deleted), 4) `SaveSystem` (HTTPType=http, FQDN=localhost, AdminEmail=admin@example.org, language=de, Timezone=Europe/Berlin), 5) `SkipMail` (guide permits skipping mail for test instances), 6) `Finish` → 302 to `/qisutu/index.pl`.
5. Triggered the completion oneshot (what the systemd path unit fires when `installed.lock` appears): `systemctl start qisutu-install-complete.service` → started `qisutu-daemon.service` (running as `qisutu`), removed the two temporary units from `/etc/systemd/system` (only `qisutu-daemon.service` remains), per the guide's "temporäre Abschlussdienste" behavior.

- Instance: `/opt/qisutu`, `var/install/instance.conf`, `var/install/installed.lock` (`installed_at=2026-01-15 14:12:46`); `core/config/QisutuConfig.pm` written with DB credentials; install log at `var/log/install.log`.
- Running processes: `mariadbd` (mysql), `apache2` (www-data, port 80), `perl /opt/qisutu/bin/qisutu-daemon.pl` (user `qisutu`, pidfile `/run/qisutu/qisutu-daemon.pid`).
- Credentials (generated by installer): admin login `admin`, password `LVRS3SUBEBF+SJQBDF_%4FYY`; DB user `qisutu`, password `V5V5@QSBXM9R%@FT@67DVYG4PQ28R7MN`.
- Access points: `http://SERVER/qisutu/index.pl` (login), `http://SERVER/qisutu/install.pl` now shows "bereits installiert". Mail not configured (skipped). Base URL registered as `http://localhost/qisutu`.

## Caveats
- "Services" are direct processes managed by the shim, not real systemd units (units exist as files; enable-state tracked in `/run/qisutu/systemctl.state`). Daemon restart is not automatic on container reboot — start via `systemctl start qisutu-daemon.service` (shim) or run the ExecStart line as `qisutu`.
