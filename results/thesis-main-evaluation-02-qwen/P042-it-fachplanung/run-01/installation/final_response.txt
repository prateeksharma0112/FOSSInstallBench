**What was done**
- ddev was assumed installed by the guide but absent → installed ddev v1.25.4 (GitHub release, linux-amd64) for a non-root user `dev` (ddev refuses to run as root; dev was added to the docker group).
- Ran the documented steps: `ddev start`, `ddev composer install`, `ddev npm i`, `ddev importDump`, `cp config/web.config.local.php.example config/web.config.local.php`.
- The `openldap` container (osixia/openldap:1.5.0) failed to start because the bundled `.ddev/docker-compose.ldap.yaml` mounts `test_users.ldif` as a `:ro` single-file bind mount, but the image's startup script requires `chown -R`, `sed -i` (rename) and `rm -rf` on that path. Fixed by mounting a writable directory (`.ddev/ldap-seed/`, containing a copy of `test_users.ldif`) at `assets/config/bootstrap/ldif/custom` and setting `LDAP_REMOVE_CONFIG_AFTER_SETUP=false`. `KEEP_EXISTING_CONFIG` stays `false` so the bootstrap loads the users.
- Performed the documented clean reset (`ddev delete --omit-snapshot -y` + `ddev start`) for a proper first start.
